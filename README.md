# Notes & Tasks — Android trainee, осень 2026

Приложение для заметок и задач на Kotlin/Jetpack Compose, написанное для тестового задания
Avito. Ниже — честный статус по разделам ТЗ на момент сдачи: что работает, что работает
частично, и что не реализовано.

## Архитектура

Multi-module, Clean Architecture, presentation — MVVM с однонаправленным потоком данных
(один `UiState` на экран). Полное дерево модулей и обоснование решений — в
[`ai-prompts-plan.md`](./ai-prompts-plan.md) (раздел 1); правила и конвенции, которых
придерживался агент при реализации — в [`CLAUDE.md`](./CLAUDE.md).

Кратко:

```
app/                единственный модуль-приложение, Hilt, NavHost, Bottom Navigation
core/common          общие абстракции, без Android-зависимостей
core/ui              Material3-тема, палитра акцентных цветов, общие composable
core/navigation      типизированные (kotlinx.serialization) route-контракты
core/database        Room: NoteEntity/TaskEntity, DAO
core/datastore       Preferences DataStore для настроек
core/network         Retrofit/OkHttp фабрики, ApiResult, safeApiCall
core/permissions     Compose-обёртка над ActivityResultContracts, состояние permission
core/media           Photo Picker / камера (FileProvider) / Coil
core/voice           запись аудио + клиент SaluteSpeech
core/gigachat        OAuth2, get-balance, chat-completion для GigaChat
feature/notes        экраны списка и редактора заметок
feature/tasks        экран задач
feature/settings     экран настроек
```

Стек: Kotlin 2.3, Jetpack Compose (BOM 2026.08), Navigation Compose, Hilt, Room, Preferences
DataStore, Retrofit + OkHttp + kotlinx.serialization, Kotlin Coroutines/Flow, Coil3.

## Исправлено в ходе самопроверки

При ревью перед сдачей нашли и поправили:

1. **Поиск не фильтровал список.** `onSearch` в `NotesListViewModel` и `TasksViewModel`
   обновлял только черновик поля ввода (`onQueryChange`), но не обновлял внутренний
   `submittedQuery` — Flow, который реально уходит в SQL-запрос через `combine`/
   `flatMapLatest`. Добавлено обновление `submittedQuery` и соответствующего поля `UiState`
   в обоих ViewModel — теперь нажатие кнопки поиска / Search на клавиатуре действительно
   переисполняет запрос.
2. **Отсутствовало разрешение `INTERNET`** в `AndroidManifest.xml` — без него не проходил ни
   один сетевой запрос (баланс GigaChat, обработка задачи через GigaChat, распознавание
   SaluteSpeech), хотя сама интеграция была реализована верно. Добавлена строка в манифест
   `app`-модуля.
3. **Отсутствовал строковый ресурс `search_clear_content_description`** — код уже на него
   ссылался, но строки не было в `strings.xml`, что ломало сборку. Добавили строку; заодно
   подключили ранее объявленный, но неиспользуемый `search_content_description` к иконке
   поиска (была без описания для скринридера).
4. **Дублирование навигационных графов.** В `MainActivity` одновременно были зарегистрированы
   рабочие top-level маршруты (`NotesTab`/`TasksTab`/`SettingsTab`) и отдельные
   `NotesList`/`TasksList`/`SettingsScreen` из `core:navigation`, на которые никто не переходил.
   Переписали `core:navigation` так, чтобы feature-графы сразу регистрировались на
   `NotesTab`/`TasksTab`/`SettingsTab`, убрали мёртвые маршруты и дублирующую прямую
   регистрацию в `MainActivity` — теперь у каждой фичи ровно один способ попасть в граф.
5. **Неиспользуемый код удалён**: `applySearchAndSort` (`core:common` — фильтрация и
   сортировка реально делаются в SQL на уровне DAO) и `isPayAsYouGoBalanceForbidden`/
   `PAY_AS_YOU_GO_FORBIDDEN_CODE` (`core:gigachat` — различение 403 реально сделано через
   `BalanceHttpException` в `feature:settings`).

## Настройка перед первым запуском

Для работы GigaChat/SaluteSpeech нужно создать `local.properties` в корне (файл
игнорируется git) и добавить: `GIGACHAT_AUTH_KEY`, `GIGACHAT_SCOPE`,
`SALUTE_SPEECH_AUTH_KEY`, `SALUTE_SPEECH_SCOPE`. Без них клиенты возвращают
контролируемую ошибку конфигурации, а не падают, но баланс/голосовое создание задач и
голосовой ввод заметок будут недоступны.

## Реализовано полностью

- **Навигация** — Navigation Compose, Bottom Navigation Bar с тремя вкладками, типизированные
  route-контракты, переход список заметок → создание/редактирование заметки.
- **Экран списка заметок** — FAB, список, поле поиска, кнопка сортировки, переключатель
  режима удаления (в режиме удаления открытие заметки по тапу заблокировано), превью
  изображения или заглушка, название, дата создания.
- **Экран заметки** — заголовок (обязателен) и текст (может быть пустым), добавление фото из
  галереи (Photo Picker, с откатом на legacy-разрешение на старых Android) или с камеры
  (FileProvider), предпросмотр и удаление изображения, голосовой ввод (распознанный текст
  добавляется к уже введённому, не заменяет его), сохранение с валидацией, состояние
  экрана переживает поворот/пересоздание процесса (`SavedStateHandle`).
- **Экран задач** — App Bar, поле поиска, фильтр по статусу (Все/Активные/Выполненные),
  FAB с выбором способа создания (текст/голос), инлайн-создание текстом прямо в списке (без
  отдельного экрана или BottomSheet, с автофокусом и завершением по клавише Done), чекбокс
  с обновлением статуса, выполненные задачи — зачёркнутый текст, сниженная прозрачность и
  отображение ниже активных независимо от сортировки (реализовано на уровне SQL-запроса).
  Голосовое создание задачи: запись → SaluteSpeech → GigaChat (переформулирование) →
  сохранение, с состояниями записи/обработки/ошибки и индикатором загрузки.
- **Экран настроек** — баланс GigaChat с состояниями загрузки/успеха/ошибки (403 из-за
  тарифа pay-as-you-go показывается отдельным понятным сообщением, а не общей ошибкой),
  выбор темы (системная/светлая/тёмная) применяется мгновенно без перезапуска, выбор
  акцентного цвета из 5 предустановленных вариантов с корректными светлой и тёмной
  версиями, кнопка сброса настроек к значениям по умолчанию.
- **Разрешения** — камера, микрофон, доступ к медиа: состояния Granted/Denied/
  PermanentlyDenied, для последнего — баннер с переходом в системные настройки приложения.
- **Хранение данных** — Room (заметки, задачи) и Preferences DataStore (настройки), везде
  реактивно через Flow, без хардкод-строк/цветов/route/секретов в коде фич.

## Не реализовано

- Автотесты (unit-тесты на use case и ViewModel не добавлены).
- Весь опциональный раздел ТЗ «Дополнительно»: стилизация текста заметки, шаринг через
  Intent, пагинация списка заметок, переключение List/Grid, подтверждение перед удалением,
  Splash Screen — осознанно не делались в пользу качества основного функционала.

## Что бы сделал с дополнительным временем

1. Покрыть unit-тестами домен-слой (валидация заголовка заметки/задачи, сортировка
   completed-ниже-active) и хотя бы один ViewModel.
2. Добавить опциональную функциональность по приоритету: подтверждение удаления → Splash
   Screen → List/Grid → шаринг заметки → стилизация текста → пагинация.

## Запуск

1. Открыть проект в Android Studio.
2. Добавить `local.properties` в корне со значениями `GIGACHAT_AUTH_KEY`, `GIGACHAT_SCOPE`,
   `SALUTE_SPEECH_AUTH_KEY`, `SALUTE_SPEECH_SCOPE` (см. раздел «Настройка перед первым
   запуском»).
3. `./gradlew assembleDebug` или запуск конфигурации `app` на эмуляторе/устройстве.
